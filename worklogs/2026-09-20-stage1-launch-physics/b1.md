# b1 · 发射与物理原型实现

日期：2026-09-21。对应目标：完成阶段 1 代码与自动化验证，提供可执行的人工试玩、调参方法。**实现完成；实际 Creator 预览和手感待用户验收，阶段未关闭。**

## 实现内容与关键文件

- `assets/scripts/core/PrototypeConfig.ts`：首组配置、有限值/范围/关系校验、冻结副本、普通与密集夹具。配置默认值及范围见 [试玩说明](../../docs/stage1-playtest.md)。
- `core/LaunchGesture.ts`：反向方向、线性力度、死区、上限、单触点拥有权、取消和重复松手隔离；`core/PhysicsPort.ts` 定义无引擎依赖的窄接口；`GameState.ts` 明确单位。
- `application/LocalMatch.ts`：只在命令接受后施加冲量；固定步进、状态采样校验、连续静止、最长模拟、异常回滚；记录 Resolving/Aiming 快照。最近 100 条命令和 100 个关键快照有界保留。
- `adapters/physics/CocosPhysics.ts`：真实 Cocos Box2D 刚体/圆形碰撞体/静态墙，零重力、质量转密度、阻尼、弹性、速度上限、bullet 连续碰撞、停止与恢复。保存并恢复全局物理设置，销毁时关闭旧物理根节点。
- `presentation/Boot.ts`：替换阶段 0 三行文字，组合应用、输入、物理、视图，处理失焦/后台/停用；重置与切换夹具建立新会话。`PrototypeView.ts` 绘制球场、球员、力度线、中文状态和按钮。
- `tests/prototype.test.cjs`：新增 17 项测试，保留阶段 0 的 18 项。README、开发说明、ROADMAP、需求差距同步实际进度。

## 关键决策

- 遵循用户“测试调试可以更多人工进行”：交付可试玩代码和详细手册，自动化与实际预览分开，不将待人工项冒充通过。
- 实现前已在 requirement-gap 记录单位、首组参数和策略。设计画布 720×1280、SHOW_ALL；场内 6.8×10.5 米，画面 80 设计单位/米；独立物理根节点按引擎常量 32 单位/米建模，避免 UI 缩放影响密度/质量。圆形固定旋转。
- 已阅读本机 Creator 3.8.8 物理源代码确认：位置需要 PTM 转换，`linearVelocity` 和冲量直接使用 Box2D 单位；手动 `step` 需要显式场景/物理同步。未改动引擎安装目录，无新增依赖。
- 固定 1/60 秒，最多 5 个补步，超出时间丢弃并提示；0.04 m/s 以下连续 18 步停止；15 秒超时强制停止。后台暂停、清空积压，恢复首帧不补后台时间。这不是正式比赛计时策略。
- 命令 ID 在当前回合防重；完成回合后清理集合，旧命令由回合号拒绝。重置使用新 matchId。异常坐标/速度、越界、缺失/重复对象或模拟抛错恢复发射前状态。此内部恢复不是联机外部恢复协议。
- 配置文件修改需重新运行预览；按钮重置只恢复摆位。默认参数尚无手感验收，校验允许范围也不等于全范围物理稳定证明。
- 保留用户已有 AGENTS、ROADMAP 及需求文档改动，基于其追加本阶段内容；未创建 Git 提交。
