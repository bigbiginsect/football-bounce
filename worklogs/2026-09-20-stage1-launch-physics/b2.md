# b2 · 首轮试玩输入修正、精度线与参数调整

日期：2026-09-21。对应目标：处理用户六项试玩反馈。用户确认问题表现为“已停止后点住蓝球拖动也没有黄色线，重复几次才行”。

## 排查证据与边界

- `LocalMatch.finish()` 在同一次调用内进入 Aiming，之后才设置 stopped；没有停止后的冷却计时。浏览器旧版实测：普通夹具第一次撞球在模拟约 7.38 秒停止，随后第一次点住当前球心向左拖动即再次发射，第二次约 3.75 秒停止。**未在浏览器直接复现编辑器的间歇失灵，不能断言用户症状的唯一根因已经证明。**
- 发现可导致相同表象的输入缺陷：`window.blur → pause()` 设 paused，但仍显示“已停止，可以再次拖动”；`beginTouch` 遇 paused 直接返回，完全依赖后续 focus/show 解锁。在缺少 focus 的事件序列里，即使收到真实前台按下也会被丢弃。增加直接调用真实 Boot 处理器的回归测试验证此事件序列。
- 原坐标转换把 `getUILocation` 的 view 缩放坐标当作 UI 世界坐标；阅读本机引擎 `UITransform.hitTest` 后改用与引擎一致的“屏幕 → Canvas 实际相机 → 球场局部”链路，消除相机/视口映射假设。普通浏览器中心位置本来可用，这一项属于适配修正，不能伪称已在编辑器测出具体偏移值。
- `temp/logs/project.log` 记录 15:39、15:48、15:49 停止预览时 `PrototypeView.dispose` 重复销毁警告，修正对应生命周期清理。

## 实现与关键文件

- `presentation/Boot.ts`：区分窗口失焦与真正后台；前台真实 TOUCH_START 可恢复失焦暂停，并继续用同一次按下选择球员。真正后台及组件停用仍拒绝输入，不放开模拟中发射。暂停提示明确显示，取消旧手势，恢复首帧仍不补后台时间。
- `presentation/PrototypeView.ts`：触点经过 Canvas 相机转换；黄色线只使用 `aimLength`，不乘 power。暂统一精度线 2 米，力度仍用百分比表示；没有提前实现完整球员资产系统。销毁时检查严格有效性，避免随场景销毁后再次 destroy。
- `core/PrototypeConfig.ts`：版本 **stage1-002**；用户明确指定的参数如下。

| 参数 | 旧值 | 新值 |

| 球员 / 皮球线性阻尼 | 1.2 / 0.7 | **0.9 / 0.5** |

- `tests/presentation.test.cjs`：通过现有 TypeScript 加载真实表现层代码，仅替换 cc 引擎边界，新增 7 项回归；无新依赖。同步试玩说明、需求差距、README 和路线图，不覆盖 b1 历史。
