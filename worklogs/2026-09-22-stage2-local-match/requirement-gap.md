# 阶段 2 · 本地双人完整对局

日期：2026-09-22 建立。**状态：实现中。**

## 目标与范围

在阶段 1 发射与物理原型上完成同一设备本地双人完整对局：创建比赛、随机先手、双方轮流操作、瞄准超时、比赛计时、进球、比分、复位、比赛结束及重新开始。规则状态继续只由 `LocalMatch` 权威入口更新，表现层只提交发射意图并读取 `GameState`。

本阶段只实现标准模式。比赛时长由模式配置提供，但不提前创建其他模式、模式选择界面或通用模式框架。

## 已确定规则

| 项目 | 决定 |
| --- | --- |
| 标准模式局时 | 3 分钟（180 秒），由当前模式配置提供 |
| 球员人数 | 蓝队、红队各 5 名 |
| 阵型 | 5 人可由未来的阵型系统排列，例如 2-2-1、1-2-2；本阶段不固定前锋/中场/后卫人数，不实现阵型选择，也不把某种阵型写成比赛规则 |
| 守门员 | 当前 5 人均为普通场上球员，不设置特殊守门员职业 |
| 先手 | 每局由规则层根据注入的随机种子决定；随机种子、当前随机状态及先手结果写入 `GameState`，重新开始创建新比赛并重新随机 |
| 换手 | 未进球时，每次运动完全停止后交换行动方 |
| 瞄准超时 | 每回合 20 秒，仅约束 Aiming 阶段；超时不发射并自动换手 |
| 比赛计时 | 覆盖瞄准和物理运动；应用层显式推进时间，不由动画回调决定 |
| 运动中到时 | 记录到时，等待当前运动及进球结算完成后结束 |
| 平局 | 到时结算后直接结束，不加时 |
| 进球 | 皮球整体越过两个门柱之间的门线才有效；一次运动最多结算一次进球 |
| 进球复位 | 双方球员和皮球恢复本局初始摆位，由失球方行动 |
| 重新开始 | 创建新 `matchId`、新随机种子及全新状态，不保留比分、计时、回合或物理残留 |

## 实现约束与可调整假设

- 蓝队 ID 为 `blue`，防守下方球门并向上进攻；红队 ID 为 `red`，防守上方球门并向下进攻。球队颜色和进攻方向属于本地标准模式的明确映射。
- 首版使用一组对称的临时初始坐标，让 10 名球员可直接开始比赛。坐标不命名为 2-2-1、1-2-2 等阵型，也不代表玩家选择；未来阵型系统应通过配置替换初始坐标，而不是修改回合或进球规则。
- 球门宽度、深度作为 stage2 配置参数先取可玩初值。门柱暂由球门口两端的墙体边缘形成，不在本阶段增加独立门柱美术资产。
- 暂停/切后台时沿用阶段 1 行为：不推进比赛或回合计时，恢复首帧不补后台时间。
- 物理异常仍恢复本次发射前快照并结束该次行动；最大模拟时长仍强制停止并进入正常结算，避免比赛永久卡住。
- 比赛到时后的 `Finished` 状态保留最终场上位置和比分；重新开始由组合层显式创建新比赛。

## 验收条件

- 每队恰好 5 人；同一随机种子得到相同先手和随机状态，不同比赛将实际使用的种子与先手写入状态。
- 双方只能操作当前行动方球员；普通回合停止后换手，20 秒无发射自动换手。
- 180 秒覆盖 Aiming 和 Simulating；Aiming 到时立即结束，Simulating 到时等本次结算，最终正确给出蓝胜、红胜或平局。
- 皮球整体越线且整体位于门柱之间才计分；边缘、未完全过线及同次模拟的重复采样不重复计分。
- 进球后比分加一、全体复位、失球方行动；到时运动中的最后一个有效进球计入最终结果。
- 重新开始生成隔离的新比赛，比分、时钟、回合、命令去重和物理状态不残留。
- TypeScript 完整类型检查和核心/表现相关自动化测试通过；Creator 3.8.8 编辑器内真实预览的人工结果单独记录，不用自动化结果代替。
