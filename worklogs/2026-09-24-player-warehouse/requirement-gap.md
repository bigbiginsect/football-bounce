# 阶段 3 · 球员仓库

日期：2026-09-24 建立，2026-09-28 追加信息页 UI 重做。状态：信息页视觉重做及自动化验证完成，等待 Creator 交互试玩。首轮开发分支：`codex/player-warehouse`，当前改动基于已合入 `main` 的交付基线。

## 目标与范围

基于现有赛前阵容流程新增独立球员仓库页面，支持从阵容主界面右滑进入、跟手滑动过渡、左滑或按钮返回；仓库展示全部球员，每名球员提供“信息”和“上场”按钮。信息卡参照用户提供的示意图，保留顶部头像/基础信息、中部五项参数、底部技能区域结构。

本批同时把“心态”“弧度”和对应俏皮话加入球员目录；两项新参数本批只用于信息展示，不改变物理或规则。技能区域只保留结构和占位文案，不实现技能效果。

2026-09-28 用户提供新的竖屏球员信息参考图，要求尤其改善 UI。追加批次保留既有仓库及弹窗交互，只重做信息页视觉层级：深色标题栏、圆形头像徽章、橙色身份区、俏皮话区、带图标/数值/分段进度条的双列属性卡、技能占位区和球场底纹。参考图中的现实俱乐部标识、号码、身高和升级条件没有对应项目数据，不复制或虚构；新增“综合”只读显示为五项现有评分的算术平均值，不写入目录或 GameState。

## 实现前状态与差距

现有 `LineupView` 在同一页面内显示固定五槽及候补横向仓库，只支持拖动候补替换和槽位交换；没有独立仓库页面、页面滑动导航、完整信息卡，也没有“信息/上场”按钮。球员目录当前只有重量、力量、精准三项评分。

## 已确定交互与数据边界

- “主界面”按当前项目实际结构指赛前阵容页，不新增与现有流程重复的首页。
- 阵容页顶部或左边缘右滑时，球员仓库从左侧跟手进入、阵容页向右退出；仓库顶部或右边缘左滑执行反向过渡，并保留明确的“返回阵容”按钮。
- 仓库顶部显示当前队伍五个上阵槽位。玩家先点选待替换槽位，再点未上场球员的“上场”；应用层复用 `LineupEditor.ReplaceFromBench`，保证队内不重复和固定位置约束不被 UI 绕过。
- 已上场球员仍保留第二个按钮位置，但显示“已上场”；点击其顶部槽位可切换待替换位置。
- 仓库编辑当前正在配置的蓝队或红队；切换队伍后使用对应阵容，双方选择继续互相独立。
- 信息卡的俏皮话、心态和弧度是可配置的游戏设计值。目录版本随字段变化更新；本批不赋予心态、弧度任何规则效果。
- 页面滑动、弹窗和滚动只产生表现/应用意图，不直接写 GameState。真正建立比赛时仍由现有阵容校验和单一命令入口处理。

## 验收条件

- 在蓝队和红队阵容页顶部或左边缘从左向右滑动，可看到仓库随手指移动并自然补间到位；短距离或反方向手势回弹，不误触阵容确认。
- 仓库可左滑或点击返回按钮回到原阵容页，当前队伍、所选槽位和阵容修改不丢失；切换期间不能重复接管触摸。
- 仓库展示目录中的全部球员；每张卡都有“信息”和“上场/已上场”按钮，球员增多时可以纵向滚动。
- 点击“信息”弹出对应球员卡，显示头像、姓名、俏皮话、重量、力量、精准、心态、弧度和空技能区域；关闭后返回原仓库滚动位置。
- 选择上阵槽位后点击候补“上场”，对应槽位被替换，原球员回到仓库可选状态；未知球员、无效槽位和队内重复不能修改阵容。
- 完整类型检查、相关自动化测试及 `git diff --check` 通过；Creator 3.8.8 中实际验证滑动、信息卡、上场、返回和双方确认。Android 真机触摸继续按支线验收。

## 依赖与范围外

依赖现有六人球员目录、头像资源、`LineupEditor` 和阶段 2 本地对局。本批不新增球员图片，首轮不实现阵型切换、自由站位、技能、养成、解锁、稀有度、联网或 Android 构建；不把参考图中的具体文字、图标或素材直接复制进项目。阵型切换和层叠抽屉已由 2026-09-28 的独立后续需求接续，见 [层叠式球员仓库与阵型选择](../2026-09-28-layered-warehouse-formations/requirement-gap.md)。
