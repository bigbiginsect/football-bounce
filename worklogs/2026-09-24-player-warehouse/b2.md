# 阶段 3 · 球员信息页 UI 重做施工记录

日期：2026-09-28  
对应目标：参照用户提供的竖屏球员信息图，重做仓库内球员属性弹窗的视觉层级，不改球员数值、比赛规则或技能效果。

## 实现内容与关键文件

- `presentation/PlayerWarehouseView.ts`：信息弹窗扩大为接近全屏的竖屏卡片，新增深色标题栏、足球标题图标、红色关闭键、圆形头像徽章、橙色身份区和俏皮话区。
- 五项现有属性改为双列大卡片，分别显示重量、力量、精准、弧度和心态；每项都有独立矢量图标、明确数值和八段进度条。
- 新增只读“综合”值，按现有五项评分的算术平均值四舍五入得到；该值只在表现层计算，不进入球员目录或 GameState。
- 技能区改为参考图式的大图标与说明卡，但文案明确标为尚未启用，不虚构技能效果或解锁条件。
- 底部增加球场线框、装饰足球和绿色“返回仓库”按钮；顶部关闭键和底部按钮都只关闭弹窗并返回原仓库位置。
- `tests/presentation.test.cjs`：补充两个关闭热区不产生仓库命令/导航意图的测试，以及综合分只读派生测试。
- `AGENTS.md`、`env_requirement.md`：按本次实际探查更新仓库目录及 Creator/Dashboard 的 E 盘安装路径；不把旧路径未找到表述为未安装。

## 关键决策

- 参考图中的俱乐部标识、号码、身高、体重单位和升级条件没有对应项目数据，因此不复制或虚构；当前 `weight` 仍作为 0—100 游戏评分显示。
- 不新增位图 UI 资源。标题足球、五项能力图标、技能徽章和球场底纹全部由 Cocos `Graphics` 绘制，随现有 720×1280 设计坐标缩放，也避免引入新的资源导入和商标风险。
- 信息页不直接改阵容或 GameState；弹窗内只有关闭意图。仓库原有“上场”仍经 `PlayerWarehouse` 与 `LineupEditor` 校验。
- 参考图底部的“升级”在当前项目没有规则入口，改为诚实的“返回仓库”，避免出现无法兑现的功能按钮。
