# 阶段 3 · 比赛圆片尺寸与首批球员技能

日期：2026-09-29 建立。状态：代码完成，待 Creator 试玩调参。

## 目标与范围

- 比赛中的球员圆片稍微增大，触摸、显示和真实碰撞半径保持一致。
- 为 C 罗加入概率型瞄准干扰：C 罗完成发射后按配置概率使对手下一次瞄准线左右摆动；显示方向和权威发射方向必须一致。
- 为内马尔加入三回合连击：按内马尔自己的正常发射次数计数，每第 3 次发射进入触发状态；本次模拟中若皮球碰到敌方球员且没有直接进球，结算后由同一内马尔追加行动一次。
- 技能状态、概率结果、计数和强制行动球员进入纯数据 GameState；物理接触经窄接口上报，UI 和物理回调不能直接改回合。

## 当前状态与差距

- 比赛球员半径为 `0.28 m`，在 720×1280 设计分辨率下外径约 44.8 像素。
- 球员目录已有通用 `skill.id/params` 预留入口，但规则层未实现任何技能，GameState 也没有技能运行状态。
- 瞄准线只读取拖动方向；规则层直接执行命令方向，没有可复现的摆动修正。
- PhysicsFrame 只上报位置、速度和进球，不上报皮球碰到哪名球员。
- 核查技能接触需求时发现现有碰撞音效回调仍按单参数签名接收事件，且动态刚体未显式启用接触监听；本批一并修正，否则技能接触和既有碰撞音效都不能依赖真实 Creator 回调。

## 实现决定与临时参数

- `playerRadius` 暂从 `0.28` 调为 `0.30 m`，约增大 7%；物理碰撞、触摸选中、开局合法性和视觉圆片共用该值。
- C 罗技能暂名 `aim-wobble`：触发概率 `35%`、最大摆幅 `9°`、频率 `1.4 Hz`。概率由既有种子随机状态推进并写回 GameState；摆动相位同样由确定性随机值生成。
- 瞄准摆动只持续目标对手的一次 Aiming：对手发射或瞄准超时后清除。规则层按同一状态时钟计算最终方向，不能仅做视觉欺骗。
- 内马尔技能 ID 为 `ball-hit-encore`，`everyTurns = 3`。只统计内马尔的正常行动；技能奖励的追加行动不再累计计数，避免奖励行动改变下一轮周期。
- 皮球接触任何敌方球员一次即可满足条件；触碰队友不算。进球、开球违例、非法物理恢复或比赛到时均优先于追加行动，不改变既有计分和终局规则。
- 追加行动在原位置继续，回合号递增并重置 20 秒瞄准时间；行动方不变，且 Command 校验只允许触发技能的内马尔实例发射。若追加行动瞄准超时，正常换边。

## 验收条件

- 比赛圆片、触摸半径和圆形碰撞体统一使用 `0.30 m`；默认三种阵型仍合法、不重叠。
- C 罗成功与失败概率都能用固定随机状态复现；成功时对手瞄准线随比赛时钟摆动，实际发射方向与当帧显示一致，效果消费后不残留。
- 内马尔第 1、2 次正常行动不武装，第 3 次武装；皮球碰队友不触发，碰敌人后正常停止或运动超时可追加一次，追加行动只能选择同一内马尔且不累计周期。
- 内马尔第三次行动未碰敌人、直接进球、开球违例、非法物理帧或比赛到时均不追加。
- 接触适配器正确使用 Creator 3.8.8 的 `(selfCollider, otherCollider, contact)` 回调，并启用动态刚体接触监听；同一步重复回调按球员实例去重。
- GameState 可 JSON 往返并保存技能计数、概率状态、摆动效果、接触满足状态和强制球员；状态版本随结构变化升级。
- 完整类型检查、相关自动化测试、`git diff --check` 通过；Creator 运行中实际观察圆片尺寸、瞄准摆动与追加行动。

## 范围外

本批不制作技能特效动画或新音效，不实现其他球员技能，不改变技能的联网同步方案，不补齐新增球员头像，不进行 Android 构建。
