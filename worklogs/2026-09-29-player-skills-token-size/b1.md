# 阶段 3 · 比赛圆片尺寸与首批球员技能施工记录

日期：2026-09-29

对应目标：略微增大比赛球员；实现 C 罗概率瞄准干扰与内马尔每第三次本人行动命中敌方后的追加行动。

## 实现内容与关键文件

- `core/PrototypeConfig.ts`：配置升级为 `stage3-004`，球员半径由 `0.28 m` 调至 `0.30 m`；比赛状态升级为 schema 5，并把球员模板技能复制为纯数据场上实例。
- `resources/config/players.json`、`core/PlayerCatalog.ts`：目录升级为 `players-005`；C 罗配置 `aim-wobble`（35%、9°、1.4 Hz），内马尔配置 `ball-hit-encore`（每 3 次）；加载时校验参数范围，仓库详情显示中文技能名和实际效果。
- `core/GameState.ts`、`core/PlayerSkills.ts`：新增技能计数、摆动效果、模拟期命中标记及奖励行动强制球员；表现层和权威执行层共用同一摆动方向计算。
- `application/LocalMatch.ts`、`core/validateCommand.ts`：用既有种子随机状态判定 C 罗效果；只累计内马尔正常行动，第三次武装后根据敌方接触授予本人追加行动；奖励行动不累计，并处理进球、开球违例、非法物理状态与比赛到时的优先级。
- `core/PhysicsPort.ts`、`adapters/physics/CocosPhysics.ts`：固定步上报皮球接触的球员实例并去重；显式启用动态刚体接触监听，同时把既有碰撞冲量处理改为 Creator 3.8.8 的三参数回调签名。
- `presentation/PrototypeView.ts`、`presentation/Boot.ts`：瞄准线随权威时钟摆动，实际发射使用同一方向；追加行动只允许触发技能的内马尔，HUD 显示技能状态。
- `tests/player-skills.test.cjs` 及既有测试：覆盖正式概率复现、成功/失败、瞄准与发射一致、前两次不触发、第三次敌我接触差异、奖励行动锁定/不累计，以及各类结算优先级。

## 关键决策

- “每 3 回合”按内马尔本人的正常发射次数解释；选择其他球员行动不会累计内马尔，奖励行动也不累计，避免连锁改变周期。
- C 罗干扰不只摇动画面；瞄准线和规则层发射均读取同一 GameState、回合时钟与随机相位，保证玩家看到的方向就是实际方向。
- 内马尔追加行动要求皮球在已武装的该次模拟中接触敌方球员。进球、开球违例、非法物理恢复和比赛结束优先，不能绕过原有计分或终局规则。
- 技能配置值均为本批可调假设；实际试玩后可只改目录参数并升级版本，不需重写规则流程。
