# 阶段 1 · 试玩与调参

当前代码与 46 项常规自动化测试已完成（stage1-003），另有 12 项真实 Box2D 贴墙对照测试通过。**2026-09-21 用户试玩后确认阶段 1 收工**，stage1-003 作为当前交付基线。下方清单保留供后续改动回归使用；关闭依据见 [验收结论](../worklogs/2026-09-20-stage1-launch-physics/requirement-gap.md)。此原型只操作蓝方，不计分、不换手、不计比赛时间。

## 第一次运行

1. 使用 Creator **3.8.8** 打开迁移后的工程 `D:\GameProjects\football-bounce-git`，等待新增脚本导入完成。本页是 stage1-003 历史回归清单；当前主界面版本已进入 stage2-001。资源 `.meta` 由编辑器生成，不要自行复制或更改 UUID。
2. 双击 `assets/scenes/Boot.scene`。选择 **Preview In Editor（编辑器内运行预览）**，点击运行。场景编辑视图本身不会显示运行时生成的球场。
3. 预览设为竖屏，先用 **720×1280**；显示不完整时调低预览缩放比例。应看到绿色球场、蓝色己方、红色对方、白色皮球、两枚按钮。游戏自身使用等比适配，额外黑边正常。
4. 按住蓝色球员中心，向下拖动，再松手：白色虚线向上，蓝色球员向上撞球。拖得越远，球员周围的半透明浅橘黄色圆越大、力度越大；圆达到上限后不再扩大，白色虚线长度保持不变；状态显示“运动中”时不能再次发射。所有物体停止后继续拖动。
5. “重置摆位”恢复当前夹具；“切换测试摆位”依次切换普通、密集、贴墙、角落夹具。运动中也能重置。持有瞄准手势时按钮不执行，避免第二个触点打断手势。
6. 若出现红色控制台错误或“原型启动失败”，记录完整第一条错误。若提示 Box2D，请检查项目设置的功能裁剪启用了 **2D 物理 → Box2D**；当前工程已选择该模块。不要改成仅碰撞检测的 Builtin。

## 建议按顺序验收

| 操作 | 预期结果 |
| --- | --- |
| 分别上下左右、斜向拖动 | 发射方向与拖动相反，白色虚线指向实际发射方向，长度不随力度变化 |
| 轻点松手、极短拖动 | 死区内取消，不发射、不增加操作次数 |
| 从很短拖距逐步拉到 100%，继续向外拖 | 力度平滑增加，上限保持 100%；死区外非常小的力度可能只产生微小移动 |
| 尝试拖动红方或皮球；运动中再拖蓝方 | 不发射、不改变当前运动 |
| 普通摆位：蓝方向上撞球，再尝试撞红方、四边与角落 | 有碰撞与反弹，没有明显穿透或跑出球场 |
| 密集摆位：向上及略偏左／右满力度发射 | 连续碰撞可结束，无永久抖动、明显穿透 |
| 两种摆位各做 10 次，总共至少 20 次 | 每次运动停止后均可继续操作，停止位置与画面一致 |
| 拖动过程中切到其他窗口，松手，再返回 | 瞄准取消并提示暂停，不意外发射；返回后第一次按住蓝方即可继续拖动，不应额外点击解锁 |
| 运动中切出窗口 5 秒再返回 | 保持暂停期间的状态，恢复后继续，不补算后台 5 秒 |
| 运动中点重置，连续重置几次，再发射 | 原摆位、速度归零、无残留瞄准线或重复发射 |
| 停止预览再运行 | 可正常重玩，无重复图形、监听或脚本错误 |
| 再用 **720×1600** 预览 | 全场与按钮可见，球场宽:高仍为 68:105，圆不变椭圆；触点命中一致 |
| 真实支持多点触摸时：第一指拖动，第二指按下／移动／松开 | 第二指不能接管、发射、取消第一指手势；第一指松手只发射一次 |

桌面鼠标不能证明真机多点触摸已通过。输入状态机的多点、取消与重复松手已自动测试；Android 触屏和生命周期留到路线图支线实测。

## 本轮重点：贴墙与力度显示

- 用户已确认上一版的拖动失灵修复有效。当前先核对底部为 **stage1-003**。
- 点击“切换测试摆位”两次到“贴墙”，向左拖蓝球后松手，使其向右撞白球。再切到“角落”，向左下拖蓝球，使其向右上撞白球。分别试半力度与满力度，观察能否离开墙面，而非只沿墙滑行。
- 靠墙且法向几乎静止的物体会被轻微内移，默认最多约 3.2 个设计单位。这是防止持续接触夹住球的可调处理，不是增加反弹速度；没有碰撞时不应持续漂移或抖动。
- 按住蓝球逐渐增加拖距，透明浅橘黄色圆应与球员同心并平滑变大，100% 后封顶；白色虚线保持等长。松手、取消或失焦后圆与线都应消失。

## 如何调手感

集中编辑 [PrototypeConfig.ts](../assets/scripts/core/PrototypeConfig.ts) 顶部的 `prototypeConfig`。**停止预览 → 修改数值与 version → 保存 → 等待编译 → 重新运行**。当前会话冻结配置，单击“重置摆位”只重置位置，不热加载文件。无须在场景检查器里逐个改刚体。

每轮只改一组参数，先用普通摆位比较，再用密集摆位复验。恢复默认值可照下表还原，不要整体还原文件而丢失后续代码。

| 字段 | 默认值 | 含义／允许范围 |
| --- | --- | --- |
| `version` | `stage1-003` | 非空版本文本，建议每组调参递增，例如 `stage1-004` |
| `playerRadius` / `ballRadius` | 0.28 / 0.15 | 半径（米）；球员 0.1～0.4，皮球 0.08～0.2 |
| `playerMass` / `ballMass` | 2 / 0.45 | 质量（kg）；均 0.1～10；同冲量下质量越小，初速度越大 |
| `maxImpulse` | 14 | 满力度冲量（kg·m/s）；0.1～30。当前用户指定 14；后续每次小幅调整并比较 |
| `playerDamping` / `ballDamping` | 0.9 / 0.5 | 线性阻尼；均 0～10。越大停得越快；皮球滑得太久优先增加 ballDamping |
| `playerRestitution` / `ballRestitution` / `wallRestitution` | 0.75 / 0.85 / 0.85 | 弹性；0～1。越大越弹，Box2D 接触采用两者中较大的弹性，因此降低弹性时应一起检查碰撞双方 |
| `friction` | 0.15 | 接触摩擦；0～1。不是球场滚动阻力，不接触其他物体时减速主要靠阻尼 |
| `maxSpeed` | 12 | 速度上限（m/s）；0.5～20。防止高冲量失控，会截断质量很小的物体的最高速度 |
| `dragDeadZone` | 0.08 | 取消拖距（米）；0～0.5。设计画面中约 6.4 单位 |
| `fullPowerDrag` | 1.5 | 满力度拖距（米）；0.1～3，必须大于死区。默认设计画面中 120 单位 |
| `aimLength` | 2 | 精度对应的固定瞄准线长度（米）；0.1～3。有效拖动期间不随力度增长，力度看透明圆及百分比；不预测碰撞或反弹 |
| `stopSpeed` | 0.02 | 静止阈值（m/s）；0.001～0.2。过大会出现明显“突然刹停” |
| `quietSeconds` | 0.3 | 全部物体连续低于阈值的时长；0.05～2 秒 |
| `maxSimulationSeconds` | 15 | 最大模拟时间；0.1～60 秒。到时清零速度，保留位置并提示超时 |
| `fixedStep` | 1 / 60 | 固定物理步长（秒）；1/120～1/30。先保留默认，修改后必须重新检查碰撞 |
| `maxSubSteps` | 5 | 单渲染帧最多补步数；1～10 的整数。卡顿超出的时间丢弃并显示“卡顿已限步” |
| `wallReleaseGap` / `wallContactTolerance` | 0.04 / 0.015 | 贴墙释放间隙 / 接触带（米）；允许 0.02～0.1 / 0.005～0.03，间隙必须大于接触带。法向接近静止时才分离位置，不额外加速 |
| `aimDashLength` / `aimDashGap` | 0.12 / 0.08 | 白色虚线每段长 / 空隙（米）；均 0.02～0.5 |
| `powerCircleMaxRadius` / `powerCircleOpacity` | 0.9 / 0.22 | 满力度圆半径（米）/ 不透明度；允许 0.4～2 / 0.05～0.5，圆半径必须大于球员半径。0.22 即约 78% 透明 |
| `wallThickness` | 0.25 | 外侧封闭墙厚（米）；0.1～1 |
| `fieldWidth` / `fieldHeight` | 6.8 / 10.5 | 本阶段固定尺寸，不允许改比例；显示使用 80 设计单位/米 |

校验允许范围只是输入安全边界，**不是整个范围都已实测稳定**。建议先调质量和冲量，再调阻尼，最后调弹性与停止阈值。圆形物体固定旋转；密度由质量和半径计算，不另设角阻尼或密度字段。大幅调整半径、速度、步长后必须重新测试最高力度和密集碰撞。

## 可选的异常结束验证

1. 记录原值，临时将 `maxSimulationSeconds` 改为 `0.1`，重新运行后满力度发射。约 6 个固定步后应提示“运动超时，已强制停止”，物体停留在当时位置，并能再次发射。之后恢复 `15`。
2. 临时把 `playerMass` 改为 `0`，重启预览，应显示启动失败并指出配置字段；恢复 `2` 后可正常启动。这验证非法配置不会静默进入物理。
3. 非有限采样、越界、物理异常及卡顿限步通过自动化替身测试覆盖；不要求手工制造损坏的物理坐标。真实碰撞是否触发不必要的恢复，仍要在正常试玩中观察。

发来一段即可：`配置版本 / 预览尺寸 / 普通或密集 / 拖动方向与力度 / 实际现象 / 希望如何变化`。例如：“stage1-001，720×1280，普通，向下拖到 100%，球很快停了，希望再滑远一些。”

如遇异常，加上控制台第一条错误及发生前的操作。阶段 1 已关闭。后续修改物理、输入或屏幕适配时，按本清单复测，并将新结果追加至相应施工记录；Android 真机项目仍按路线图支线验收。
