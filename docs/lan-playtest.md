# 附近联机试玩与验证

当前为首批代码实现，尚无可交付APK或双手机验收记录。先在Creator 3.8.8导入资源及脚本，再在具备既有Android工具链的机器打包，不在本机安装工具链。

## 使用步骤

1. 两台手机安装同一次构建的APK。手机A在系统设置开启热点，手机B连接该热点；也可以两台连接同一个允许设备互访的Wi-Fi。
2. A打开游戏，点“附近联机 · 创建房间”，作为蓝队房主。A需保持游戏前台运行。
3. 热点模式下，B在系统Wi-Fi详情中查看“网关/路由器”地址（通常就是A的热点地址）；回到游戏输入该IPv4地址，点“附近联机 · 加入房间”。同一普通路由器模式要输入A自己的局域网IP，而不是路由器网关。IP依厂商和网络变化，不能固定使用示例地址。
4. 默认端口8765，地址框也接受 `192.168.43.1:8765` 这样的IP:端口形式。示例不是本机实际地址。首版不自动搜索房间，不接受房间码，也不会自动开启热点。
5. 双方在各自设备点“选择我的阵容”，布置自己的五名球员和阵型，再点“确认阵容 · 准备比赛”。已准备后等待对方；首版准备后不撤回，如需改选可退出重新建房。双方准备完自动开赛，先手仍按种子随机。
6. 仅在自己的回合拖动己方球员。红队仍显示在球场上方，首版不旋转视角。比分、剩余时间、运动及结局均由A统一计算，B不自行模拟。
7. 比赛结束点“再来一局”，双方回到选人准备流程，保留上一局阵容选择和房主本次启动状态。双方再次确认才开新局；比赛中没有单方重开。
8. “退出房间”、切后台/失焦或断线会中止本场，另一方收到退出/断线提示；无通知的断网最多等待约8秒后超时。首版不恢复旧局、不迁移房主，不把中止算作输赢。需要重新建房加入。

## 打包前核对

- 使用Creator **3.8.8**，打开 `assets/scenes/Boot.scene`。让编辑器为新增网络目录、TS脚本自动生成 `.meta`，随源码保留；本批因编辑器无法启动未生成，不手工伪造UUID。
- 项目设置→功能裁剪中启用 `WebSocket` 和 `WebSocket Server`。共享 `settings/v2/packages/engine.json` 已开启两项，打包机器仍应检查最终原生配置包含对应模块。APK运行时缺少WebSocketServer会明确提示不能创建。
- 本地核对的Creator3.8.8 Android模板包含INTERNET、ACCESS_NETWORK_STATE、ACCESS_WIFI_STATE及 `usesCleartextTraffic="true"`。这只是模板检查，不是本项目APK验证；检查实际生成/合并的Manifest及目标Android系统要求。
- 不租服务、不运行电脑服务程序。手机热点建立局域网即可，附近模式不依赖互联网；路由器的访客隔离或厂商热点限制可能阻止互访，须真机确认。
- Web/编辑器内的浏览器预览可检查模式菜单、输入错误、不能创建房间的提示和原有同机玩法；不能用它来证明手机监听端口成功。

## 自动化检查

正常开发终端沿用 `npm.cmd run check`。当前工作环境没有npm入口，已复用既有依赖执行等价命令：

```powershell
node node_modules/typescript/bin/tsc --project tsconfig.json --noEmit
node node_modules/typescript/bin/tsc --project tsconfig.core.json
node --test tests/*.test.cjs
git diff --check
```

网络专项：`node --test tests/lan-match.test.cjs tests/lan-socket.test.cjs`。

协议测试用进程内消息队列及假物理验证；适配器事件用Cocos API形状替身验证。真实WebSocket回环测试额外使用Node内置WebSocket及仅测试用途的回环服务，运行在临时端口，不作为游戏服务交付。若操作系统/沙箱返回EACCES或EPERM，该项明确跳过；在允许回环通信的普通终端应实际通过。均不能代替Cocos原生模块或Android真机。
